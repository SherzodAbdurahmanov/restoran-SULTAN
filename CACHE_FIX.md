# Исправление проблемы с кешем меню

## Проблема
После того как администратор изменял доступность блюда (включал/выключал), в меню продолжало отображаться старое состояние. В админке статус обновлялся корректно, но посетители сайта видели устаревшую информацию.

## Причина
Данные меню кешировались в `localStorage` на 5 минут для ускорения загрузки. При изменении доступности блюда в админке, кеш не очищался, поэтому пользователи продолжали видеть старые данные из кеша.

## Решение

### 1. Создана утилита управления кешем ✅
**Файл**: `src/utils/menuCache.ts`

Централизованное управление кешем меню с методами:
- `get()` - получить данные из кеша (если актуальны)
- `set(data)` - сохранить данные в кеш
- `clear()` - очистить кеш
- `getStale()` - получить устаревшие данные (для fallback)

**Преимущества**:
- Один источник правды для всего кода
- Легко использовать в разных компонентах
- Защита от ошибок при работе с localStorage

### 2. Автоматическая очистка кеша при обновлении ✅
**Обновлен**: `src/pages/Admin.tsx`

Когда администратор меняет доступность блюда:
```typescript
// После успешного обновления в базе данных
menuCache.clear(); // Очищаем кеш
```

**Результат**: При следующем открытии меню загрузятся свежие данные из Supabase.

### 3. Использование утилиты в MenuNew ✅
**Обновлен**: `src/pages/MenuNew.tsx`

Заменен старый код с прямым доступом к `localStorage` на использование утилиты `menuCache`:

**Было**:
```typescript
const cachedData = localStorage.getItem('menu_items_cache');
// ... куча кода для проверки времени
```

**Стало**:
```typescript
const cachedData = menuCache.get();
if (cachedData) {
  setMenuItems(cachedData);
  return;
}
```

## Как это работает

### Сценарий 1: Посетитель открывает меню
1. MenuNew проверяет кеш через `menuCache.get()`
2. Если кеш свежий (< 5 минут) - показывает из кеша
3. Если кеш старый или пустой - загружает из Supabase

### Сценарий 2: Админ меняет доступность блюда
1. Admin отправляет обновление в Supabase
2. Получает подтверждение
3. Вызывает `menuCache.clear()` - **ключевой момент**
4. Локальный кеш очищен

### Сценарий 3: Посетитель обновляет страницу меню
1. MenuNew проверяет кеш - он пустой (очищен админом)
2. Загружает свежие данные из Supabase
3. Видит актуальное состояние блюд

## Преимущества решения

✅ **Мгновенное обновление** - при изменении в админке кеш очищается сразу
✅ **Быстрая загрузка** - кеш все еще работает для обычных посещений
✅ **Централизованное управление** - весь код работы с кешем в одном месте
✅ **Легко расширяемо** - можно добавить другие места очистки кеша
✅ **Безопасность** - обработка ошибок при работе с localStorage

## Дополнительные улучшения

### Когда еще очищается кеш:
- ✅ При изменении доступности блюда в админке
- 🔄 Можно добавить: При добавлении/удалении/редактировании блюд
- 🔄 Можно добавить: При изменении цены
- 🔄 Можно добавить: Кнопка "Обновить меню" для пользователей

### Возможные расширения:
```typescript
// В любом месте кода можно очистить кеш:
import { menuCache } from '../utils/menuCache';

// После любого изменения меню в админке
menuCache.clear();
```

## Тестирование

### Как проверить что исправление работает:

1. **Откройте меню как посетитель**
   - Меню загружается и кешируется

2. **Откройте консоль (F12)**
   - Должно быть: "Loaded menu items: X" или "Using cached menu data"

3. **Зайдите в админку**
   - Выключите любое блюдо
   - Должно быть: "Menu cache cleared"

4. **Вернитесь в меню (обновите страницу)**
   - Должно быть: "Loaded menu items: X" (свежие данные из Supabase)
   - Блюдо должно показываться как недоступное

5. **Включите блюдо обратно в админке**
   - "Menu cache cleared"

6. **Обновите меню снова**
   - Блюдо снова доступно для заказа
